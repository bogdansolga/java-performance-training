## Notes / exceptions

- **Row `18, 20` (CMS "Java 17" → "JDK 14")**: this anchor deliberately matches twice. I checked both occurrences byte-for-byte (deck read lines 462–463 and 519–520) — they are identical, and both need the exact same fix, so letting `gslides.sh replace`'s `replaceAllText` hit both at once is correct, not accidental collateral damage. `deck-check.sh` will still report this row as `AMBIGUOUS (2 hits)` because its checker can't distinguish "intentionally duplicated, same fix" from "accidentally duplicated, different fix needed" — that distinction needed the manual read-through above. Flagging this for the trainer's attention at the gate rather than silently forcing it into two unautomatable manual rows for something a global replace safely handles in one shot.
- **Rows with a blank Anchor (slide 22, slide 38's second row, slide 39)**: left blank on purpose. `deck-check.sh` skips rows with an empty anchor (`[ -n "$anchor" ] || continue`), and `deck-apply.sh` does too — these are genuinely un-automatable with a literal-substring, whole-deck `replaceAllText` tool:
  - Slide 22: the wrong value ("JDK 11") lives in its own text run, separate from the ("Enabled by default since") run that's actually unique. That run's text — bare "JDK 11" — also appears correctly on slides 29 and 31 (Epsilon), so a global replace would corrupt those. And any replacement text for the safe run would need a preserved trailing space to join cleanly with the untouched "JDK 11" run that follows — which `deck-apply.sh`'s whitespace trim always strips, so even a "safe-looking" split anchor would silently render as run-on text ("...JDK 9JDK 11") once actually applied.
  - Slide 38 (second row): "Mainstream since Java 11" appears twice **on the same slide**, once under the (wrong) ZGC bullet and once under the (correct) Epsilon bullet. A global replace would silently corrupt the correct Epsilon line.
  - Slide 39: "Collectors overview" is a literal substring of slide 1's "Garbage Collectors overview". A global replace would silently corrupt slide 1's unrelated intro bullet.
- **Slides 37 and 38 (primary row)**: both anchors were deliberately chosen to start and end on a real word, never on the space that joins them to a neighboring, untouched text run — so the leading `" - "`/`" "` stays exactly as-is (it's outside the matched anchor, so `replaceAllText` never sees it) and the visible result reads correctly with no dependency on whitespace surviving the field-trim. E.g. slide 37: `"CMS"` (untouched run) + `" - "` (untouched) + anchor `"concurrently collects…"` → replaced with `"concurrently collects…running (JDK 11 only; removed in JDK 14)"` reads as `"CMS - concurrently collects the old generation, while app threads are running (JDK 11 only; removed in JDK 14)"`.
- **Slide 27/28 addition row**: the brief listed this as slide 27; the live deck has it on slide 28 ("Shenandoah GC, continued"). Slide 27 is the Shenandoah intro slide.
- **Slide 37 (CMS summary)**: the brief proposed `removal` here ("CMS no longer exists on any covered release"), but that premise is wrong — JDK 11 is a covered release and CMS does exist there (deprecated, not yet removed). Per the trainer's ground-truth correction, this row scopes the claim to JDK 11 instead of deleting it.
- Every non-blank anchor above was verified with `grep -o -F -- "<anchor>" /tmp/deck-5-1.txt | wc -l` printing exactly `1`, except the documented `18, 20` exception (prints `2`, by design).
